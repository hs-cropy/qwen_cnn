03연구 과정

MVP → 데이터 확장 → 데이터 신뢰성 점검 → 전체 데이터 학습 → 판별 불가 클래스 → 작업자 분리 시험셋과 개선 실험 → 라벨 재검토 순으로 진행했습니다.

1단계 · 2026-07-02 ~ 07-04
MVP 모델과 데이터 확장
  • AI Hub「노지 작물 질병 진단」(dataSetSn 147) Validation 원천 데이터로 시작: 병해 6종 → 정상 3종을 더해 9클래스.
  • 초기 데이터 476장(train 404 / val 72)으로 시작. ResNet18 모델은 val 94.4%에서 정규화만으로는 더 오르지 않음(train 정확도 100% 포화) → 데이터 확충이 우선이라고 판단.
  • Training 분할 질병 데이터를 추가해 4,246장(train 2,972 / val 637 / test 637)으로 재구성, Colab T4에서 ResNet50 학습.
결과: val 96.2% / test 93.1%. 같은 test에서 이전 모델 91.2%. 무노균병 10.5% → 71.1%.
2단계 · 2026-07-07
무 질병 혼동 분석과 미세조정 기반
  • test 오분류 44건 중 26건(59.1%)이 무검은무늬병 ↔ 무노균병 상호 혼동. 나머지 7개 클래스는 94~100%.
  • TTA(좌우반전 평균) 93.1 → 93.2%로 무의미 → 추론 변동이 아니라 분리력 문제로 판단.
  • 클래스 균형 샘플러, 해상도 옵션, 체크포인트 img_size 저장, 혼동쌍 유도촬영 설계(잎 뒷면 재촬영) 착수.
3단계 · 2026-09-17 ~ 09-18
3주차 Colab 재현과 이어학습
  • 축소 번들 val 637장 재평가 96.23%(613/637). 원본 이미지로는 94.66% — 원본 사용이 개선으로 이어지지 않음.
  • 같은 시작 모델에서 일반·균형 샘플링 이어학습 각 12 epoch → 둘 다 기준 모델을 넘지 못해 기존 모델 유지.
4단계 · 2026-09-18 ~ 09-24
데이터 신뢰성 점검과 작업자 분리 첫 기준선
  • 분할 독립성 점검: train↔val 2쌍, train↔test 4쌍이 동일 이미지(SHA256 일치) → 기존 93.1%는 완전한 일반화 성능이 아님.
  • AI Hub 공식 문서·라벨 JSON 91,041개 확인: 파일명의 날짜 앞 코드가 수집 작업자 ID임을 확인.
  • 작업자 단위 분할(4,235장)로 ImageNet 초기화부터 새로 학습: val 91.85% / Macro F1 0.9035, 256 입력 92.48%.
  • 주요 오류 사진 42장 육안 검토 — 라벨 코드는 일치, 라벨 치수 0/0 6건 발견.
5단계 · 2026-10-02 ~ 10-06
전체 데이터 학습 (36,583장)
  • 중복 제거·라벨 연결한 공식 Training 32,513 / Validation 4,070장, 긴 변 512px 사본으로 Colab 학습.
  • 기준 모델 val 99.43% / F1 0.9608 → 256 미세조정 99.58% / 0.9624, 384 미세조정 99.56% / 0.9600.
  • 그러나 무노균병 재현율 79.2% → 70.8%(256) → 62.5%(384)로 하락 → 서비스 교체 보류. 학습 crop 제거 실험도 효과 없음.
교훈: 전체 지표 상승 ≠ 목표 질병 개선. 정상이 검증셋의 88%라 전체 정확도는 거의 항상 높게 나옴.
6단계 · 2026-10-26 ~ 10-27
판별 불가(9_기타) 클래스 추가 → 10클래스
  • 손·물건 사진도 9개 중 하나로 진단되는 문제 해결을 위해 AI Hub 잎 바깥 조각 + COCO 2017 val 5,000장으로 기타 클래스 구성.
  • val 99.57% / Macro F1 0.958, 작물 사진 → 기타 1/4,070, 기타 재현율 563/565.
  • 흐림 평가(가우시안 σ2): 작물 → 기타 0.34%(채택 기준 2% 통과). 같은 조건 9클래스 모델 정확도 77.8% vs 새 모델 98.8%.
채택 PR #107로 백엔드·오프라인·프론트 10클래스 전환.
7단계 · 2026-10-28 ~ 11-02
작업자 분리 시험셋과 개선 실험 1~6
  • 공식 Validation 4,070장 중 4,063장이 Training과 같은 작업자·날짜 → val 99.6%는 새 촬영자 성능이 아님.
  • 작업자 78명을 통째로 train/val/test에 배정(seed 1568), 시험 11,434장. 기준선 Macro F1 0.899.
  • ConvNeXt, 448px, 무 전용 2단계 분류기, 병반 박스 crop, 원본 해상도 crop, seed 반복을 차례로 시험(→ 실험).
채택 448px 입력만 유효 → 전체 데이터 448px 재학습본 교체 인계.
8단계 · 2026-11-02 ~ 11-04
라벨 재검토와 제품 대응
  • 무 질병 시험 290장 + 학습·검증 499장을 원본 해상도로 육안 양상 분류 → 검은무늬병 라벨의 절반 이상이 사진에 근거 없음.
  • 라벨·양상 불일치 153장을 뺀 정리본 재학습(seed 3 vs 3) → 경계만 이동, 기각.
  • 제품: 무 질병이 1순위면 확률 차이와 관계없이 잎 뒷면 재촬영 안내(decision-v3, PR #131).

파일명의 작업자 코드(날짜 앞 토큰)로 78명을 70/10/20에 가깝게 배정, 클래스마다 시험 작업자 2명 이상. 9_기타의 AI Hub 조각은 원본 작업자를 따르고 COCO 조각은 내용 해시로 나눴습니다.

이 시험셋의 한계
  • 작업자 분리는 농장·지역 분리가 아닙니다. 무 질병은 전부 region 9, 배추 질병은 전부 region 1입니다.
  • 시험 작업자의 촬영 날짜가 학습 작업자와 상당수 겹칩니다(무노균병 9일 중 5일). 같은 밭을 여러 명이 찍었을 수 있습니다.
  • 질병 사진과 정상 사진의 작업자가 전혀 겹치지 않아, 촬영 스타일로 정상/질병을 가르는 교란은 잡히지 않습니다.
  • 무 시험 작업자는 2명뿐이라 10%p 미만의 차이는 개선으로 보지 않습니다.
  • 여러 실험의 채택 판단에 반복 사용해 448px 점수에는 선택 편향이 섞일 수 있습니다. 최종 성능은 새로 모은 밭 사진 같은 별도 평가셋으로 확인해야 합니다.

05라벨·데이터 품질 문제

성능이 오르지 않는 원인을 추적하다 발견한 데이터 쪽 문제들입니다. 가장 큰 것은 무검은무늬병 라벨의 혼재입니다.

분할 오염

분할 간 동일 이미지 6쌍

확장 v1에서 train↔val 2쌍, train↔test 4쌍이 원본 SHA256까지 동일. 파일 단위 무작위 분할의 결과로, 초기 test 93.1%는 완전한 일반화 성능이 아닙니다.

작업자 누수

공식 val의 99.8%가 학습 작업자

AI Hub 공식 Validation 4,070장 중 4,063장이 Training과 같은 작업자·날짜 묶음. 공식 분할로 잰 99%대 정확도는 새 촬영자 성능을 보여 주지 못합니다.

메타데이터

비어 있거나 깨진 필드

라벨의 worker 필드 전부 공란(파일명에서 복원), 원본 크기 0/0 라벨 43장(박스 사용 불가), 날짜 불일치 2건, Colab unzip 시 한글 클래스명 깨짐(복원 후 재저장).

무검은무늬병 라벨의 혼재 — 육안 양상 분류

원본 해상도(5472×3648) 병반 crop을 보고 병명이 아니라 보이는 양상으로 분류했습니다. 식물병리 전문가의 판정이 아니라 1차 검토이며, "라벨 의심"은 확정이 아니라 전문가 검토 우선순위입니다.

기각

1. ConvNeXt-Tiny

Macro F1 +0.006, 무노균병 +6.4%p로 기준 미달. 무검은무늬병 → 무노균병 오류는 77 → 83장으로 오히려 늘었습니다. 혼동은 백본 용량 문제가 아닙니다.

채택

2. 입력 448px

원본이 512px이라 448은 병반 질감을 거의 그대로 씁니다. 무노균병 +14.1%p(노균 → 검은무늬 오류 16 → 8장), 나빠진 클래스 없음. 무검은무늬병은 그대로(85장이 여전히 노균병으로). 추론 연산은 약 3배.

기각

3. 무 전용 2단계 분류기

전용 단독 65.9% vs 본 모델 63.4%(McNemar p=0.47, 차이 없음), 재분배 규칙으로 합치면 60.0%로 악화. 전용 모델은 심한 검은무늬병을, 본 모델은 가벼운 검은무늬병·노균병을 맞혀 서로 다른 사진을 맞히지만 합산 규칙이 장점을 못 살립니다. ENABLE_PAIR_MODEL=false 유지.

기각

4. 병반 박스 crop

가설: "모델이 병반이 아니라 배경·계절 단서로 판정한다." 병반만 보고 학습·평가해도 균형 정확도 67.4%로 기존(71.4%)보다 낮아, 배경을 치워도 혼동은 그대로입니다. 배경 단서 가설 기각.

→ 실험 6에서 기각

5. 원본 해상도 crop

08제품 쪽 대응 — 혼동쌍 유도촬영

모델로 풀리지 않는 혼동은 사진을 한 장 더 받아서 풉니다. 노균병의 흰 곰팡이는 잎 뒷면에서 확인되기 때문입니다.

재촬영 조건 (decision-v3)

  • 첫 사진의 1순위가 무 질병이면 확률 차이와 관계없이 잎 뒷면 근접 재촬영을 요청합니다(trigger=top1).
  • 배추 혼동쌍(검은썩음병 ↔ 노균병)은 상위 두 후보가 쌍이고 차이가 0.20 미만일 때 잎맥·가장자리 재촬영.
  • 이전 게이트(쌍 일치 조건)는 무 오류의 49%만 잡았습니다 — 나머지 오답은 2순위가 다른 클래스였기 때문.

다시점 융합

두 번째 사진은 판별 부위를 겨냥해 찍은 것이므로 더 큰 가중치를 줍니다.

fused[c] = 0.4 · 첫 사진[c] + 0.6 · 재촬영[c]

판별 단서: 뒷면 회백색 포자층 → 노균병 / 뒷면 깨끗 + 앞면 동심원 병반 → 검은무늬병. 배포 전 식물병리 자료로 검증이 필요합니다.
