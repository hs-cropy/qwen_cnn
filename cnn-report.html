02모델 사양과 클래스 정의

ImageNet 사전학습 ResNet50을 미세조정한 이미지 분류기입니다. 진단 결과는 백엔드 DB의 병해 정보와 model_class_id로 연결됩니다.

항목값

입력RGB, 256px(현재 운영 서버) → 448px(교체 후보, 미반영), ImageNet 정규화
출력10클래스 softmax, 상위 3개 + 전체 분포 반환

증강RandomResizedCrop(0.7~1.0), 좌우반전, 회전 ±15°, ColorJitter, 가우시안 흐림

03연구 과정

사전 실험 → 팀 저장소 첫 모델 → 평가 신뢰성 점검 → 작업자 분할 v0 → 전체 데이터 학습 → 원인 조사 → 판별 불가 클래스 → 무 전용 분류기 재검증 → 작업자 분리 시험셋 v1 실험 → 라벨 재검토 순으로 진행했습니다. 각 단계의 상세 수치는 실험 대장에 모았습니다.

0단계 · 2026-07 (팀 저장소 이전 개인 실험 기록)
사전 실험 — 데이터 확장의 효과 확인
  • AI Hub「노지 작물 질병 진단」(147) Validation 원천 데이터 476장(train 404 / val 72)으로 시작. ResNet18은 val 94.4%에서 정규화만으로는 더 오르지 않음(train 100% 포화).
  • Training 분할 질병 데이터를 추가해 4,246장으로 재구성 → 같은 test에서 이전 모델 91.2% → 93.1%, 무노균병 10.5% → 71.1%.
출처: 당시 작업 메모. 팀 저장소에는 근거 파일이 없어 참고값으로만 둡니다.
1단계 · 2026-09-03
팀 저장소 첫 모델 — 9클래스 ResNet50
  • 처음부터 9클래스(병해 6 + 정상 3). ResNet50, 입력 224, train 2,972 / val 637 / test 637(파일 단위 무작위 분할, 정상은 클래스당 200장 상한, 무노균병 175/38/38).
  • 원본 이미지 평가: val 94.7% / test 93.1%. test 무검은무늬병 68.0%(51/75), 무노균병 71.1%(27/38).
  • test 오분류 44건 중 26건(59.1%)이 무 쌍(검은무늬→노균 19, 노균→검은무늬 7). 배추 쌍은 3건 → 혼동쌍 유도촬영 설계의 근거.
  • 보조 무 쌍 분류기 pair_mu.pth(ResNet18) test 76.1%(113장). 해상도 실측 val 224 94.7% / 256 94.5% / 288 95.3%(4장 차이).
2단계 · 2026-09-17 ~ 09-18
Colab 재현과 평가 신뢰성 점검
  • 같은 체크포인트·224에서 축소 번들 val 96.23%(613/637) vs 원본 94.66%(603/637). 무검은무늬병 94.67% vs 77.33% — 원본 입력이 오히려 낮아 기존 전처리 유지(PR #22).
  • 일반·균형 샘플링 이어학습 각 12 epoch(lr 2e-5) → 최고 약 96.2% / 96.1%로 기준 모델을 넘지 못해 저장 안 됨.
  • 분할 감사(PR #23): train↔val 2쌍, train↔test 4쌍이 동일 이미지 → 93.1%는 독립 성능이 아님.
3단계 · 2026-09-21 ~ 09-29
데이터 출처 조사와 작업자 분할 v0
  • AI Hub 가이드라인 6쪽: 파일명의 날짜 앞 토큰은 수집 작업자 ID, S01은 동일 객체 촬영 순서. 박스는 병반 마스크가 아니라 관찰 객체 박스.
  • 라벨 JSON 91,041개로 4,246장 전부 1:1 연결. 정상 1,500장 전부가 공식 Validation 출처라 기존 분할은 공식 분할을 섞은 것이었음. 동일 바이트 그룹 11개.
  • 작업자 단위 분할 v0(4,235장, train 2,728 / val 785 / test 722)으로 ImageNet부터 재학습: 224 val 91.85% / F1 0.9035, 256 92.48% / F1 0.9099.
  • 오류 사진 검토(42장, 59장): 라벨 코드는 모두 일치, 변경 근거 없음. 무 학습 사진 513장 촬영면 전수 태깅 — 뒷면 사진이 두 클래스 모두에 많아 "학습에 뒷면이 없어서"라는 가설은 기각.
4단계 · 2026-10-02 ~ 10-06
전체 데이터 학습 (36,583장)
  • 중복 제거한 공식 Training 32,513 / Validation 4,070장, 긴 변 512px 사본. 검증셋의 88.30%가 정상이라 모델 선택 기준을 정확도 → Macro F1로 변경.
  • 기준 모델 val 99.43% / F1 0.9608. 학습 crop 제거(99.43%, F1 0.9590), 256 미세조정(99.58% / 0.9624), 384 미세조정(99.56% / 0.9600).
  • 미세조정할수록 무노균병이 나빠짐: 19 → 17 → 15/24, 노균→검은무늬 오류 3 → 6 → 9. 무검은무늬병은 69 → 71 → 76/76 — 결정 경계만 이동.
  • 무 오류 검토: 모델은 학습셋 무노균병 227/227, 무검은무늬병 457/462를 다 맞히고 검증에서 틀림 → 일반화 실패.
교훈: 전체 지표 상승 ≠ 목표 질병 개선. 서비스 교체 보류.
5단계 · 2026-10-08 ~ 10-25
원인 조사와 경량 배포 준비
  • 무노균병 오답 사진을 좌우 반전만 해도 검은무늬병 88.46% → 노균병 80.05%로 판정이 뒤집힘. 특징 공간의 최근접 학습 사진도 통째로 바뀜(→ 원인 조사).
  • 입력 조건 실험: 병반 박스 안을 가리면 무노균병 19 → 5/24 → 모델은 실제로 병반을 봄.
  • 브라우저 오프라인용 FP32 ONNX 변환: PyTorch 대비 최대 logit 차이 1.4×10⁻⁶. PC CPU 추론(224) 예열 후 중앙값 166ms.
  • 반전 일관성 손실(JS) 학습: 대조군·실험군 모두 최고 모델이 학습 전(epoch 0)이고 지표가 동일(99.43% / F1 0.9608). 마지막 epoch 반전 판정 변화율 0.49 → 0.47%만 줄고 무노균병은 둘 다 70.83% → 기각.

분할 오염

분할 간 동일 이미지 6쌍

초기 분할에서 train↔val 2쌍, train↔test 4쌍이 원본 SHA256까지 동일(동일 바이트 그룹은 분할 내부 포함 11개). 정상 1,500장은 전부 공식 Validation 출처라 공식 분할이 섞여 있었습니다. 초기 test 93.1%는 완전한 일반화 성능이 아닙니다.

공식 val의 99.8%가 학습 작업자

3. 무 전용 2단계 분류기

12제품 쪽 대응 — 혼동쌍 유도촬영

모델로 풀리지 않는 혼동은 사진을 한 장 더 받아서 풉니다. 노균병의 흰 곰팡이는 잎 뒷면에서 확인되기 때문입니다.

재촬영 조건 (decision-v3)

  • 첫 사진의 1순위가 무 질병이면 확률 차이와 관계없이 잎 뒷면 근접 재촬영을 요청합니다(trigger=top1). 운영 서버 적용 확인.
  • 배추 혼동쌍(검은썩음병 ↔ 노균병)은 상위 두 후보가 쌍이고 차이가 0.20 미만일 때 잎맥·가장자리 재촬영.
  • 이전 게이트(쌍 일치 조건)는 무 오류의 49%만 잡았습니다 — 나머지 오답은 2순위가 다른 클래스였기 때문.

다시점 융합

두 번째 사진은 판별 부위를 겨냥해 찍은 것이므로 더 큰 가중치를 줍니다.

fused[c] = 0.4 · 첫 사진[c] + 0.6 · 재촬영[c]

판별 단서: 뒷면 회백색 포자층 → 노균병 / 뒷면 깨끗 + 앞면 동심원 병반 → 검은무늬병. 배포 전 식물병리 자료로 검증이 필요합니다.
